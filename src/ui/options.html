GutterHub settings

Coverage gutters on GitHub pull requests, file views and commits. Documentation

General

GitHub access

Needed to download Actions artifacts and to read private repositories. A classic token needs repo; a fine-grained token needs Actions: read and Contents: read. Stored in extension storage and only ever sent to the GitHub host you are browsing.

Comma-separated. GutterHub will ask for permission to run on these hosts when you save.

Azure DevOps access

Only needed for the Azure DevOps report source — for repositories that live on GitHub but build in Azure Pipelines. Needs Build (read) scope. This is a different credential from the GitHub token above; neither is ever sent to the other service.

Repositories

Nothing configured yet. Report sources are set up in the popup, not here — open a repository, pull request or file on GitHub, click the GutterHub toolbar icon, and choose where its reports come from. Each repository is remembered separately, so you can point every project at wherever its own CI publishes.

Path mapping

Coverage reports spell paths differently from the repository — absolute CI paths, paths relative to a project folder, or bare file names. GutterHub matches on the longest common path suffix, which handles most reports without configuration. Use these only when a file that should have coverage shows none.
